# 设置

![](./assets/settings.svg) 从"文件"菜单打开设置。

窗口分为五个部分，列在左侧：**核心**、**外观**、**控制**、**翻译**、**项目**。设置在关闭窗口时自动保存——如果某个字段包含无效值（例如超出范围的备份周期），窗口将拒绝关闭并指向违规字段。

核心、外观和控制设置全局存储一份。翻译和项目设置按**项目**存储，因此不同项目可以使用不同的翻译服务、语言和检查配置。

## 核心

### 备份

| 设置 | 说明 |
| ---- | ---- |
| 启用 | 开启或关闭自动项目备份。 |
| 备份周期 | 创建备份的频率，以秒为单位（60-3600）。 |
| 最大备份数 | 每个项目保留的备份数量上限，超出后删除最早的备份。 |

如需恢复备份，请使用"文件 > 加载备份"。它按日期列出项目的备份，并警告你加载备份会**覆盖你当前的未保存进度**——请先确认这正是你想要的。

### 更新

| 设置 | 说明 |
| ---- | ---- |
| 启动时检查更新 | 启动时检查是否有新的应用程序版本。 |
| 检查源文件更新 | 检查游戏源文件自上次读取以来是否有变动，如有变动则提供重新读取选项。 |

### Git

提交时使用的身份，来自内置的 [git 客户端](./git.md)。

| 设置 | 说明 |
| ---- | ---- |
| 优先使用仓库的 git 配置 | 如果仓库已在自身的 `git config` 中设置了作者身份，则使用该身份，而非下方字段。 |
| 姓名 / 邮箱 | 提交时的作者身份，在不遵从 `git config` 时使用。 |

## 外观

| 设置 | 说明 |
| ---- | ---- |
| 翻译表字体 / 字号 | 翻译表中使用的字体和字号（8-96 磅）。 |
| 样式 | Qt 控件样式——影响按钮、列表及其他控件的外观。 |
| 主题 | 浅色、深色或跟随系统。 |
| 语言 | 应用程序自身的 UI 语言（英语或俄语）。 |
| 显示百分比 | 在标签面板中以百分比而非原始条目数量显示任务进度。 |

## 控制

用于打开面板和菜单的键盘快捷键。点击快捷键字段，然后按下你想要的组合键。

| 操作 | 默认 |
| ---- | ---- |
| 搜索面板 | `Ctrl+R` |
| 标签面板 | `Tab` |
| 跳转到行 | `Ctrl+G` |
| 批量菜单 | `Ctrl+B` |
| 书签菜单 | `Alt+B` |
| 检查菜单 | `Ctrl+M` |
| 术语表菜单 | `Alt+B` |
| 翻译菜单 | `Ctrl+S` |

同一个快捷键不能同时分配给两个操作——如果存在重复，关闭窗口的操作会被拒绝，直到你修改其中一个。

## 翻译

这是最大的部分。配置机器翻译服务、LanguageTool 和检查系统。

API 密钥绝不会写入 `settings.json`——它们保存在你操作系统的凭据存储中（Windows 凭据管理器，或 Linux 上的 Secret Service 密钥环），仅在需要时读取。

### 翻译服务

翻译服务列在此部分左侧；使用列表上方的按钮添加或删除。每个翻译服务包含：

| 设置 | 说明 |
| ---- | ---- |
| 单独翻译 | 启用后，编辑某个翻译单元格时也会通过此翻译服务翻译源文本，并在翻译菜单中显示结果。注意使用付费 LLM API 时——每次编辑都会消耗额度。 |
| 使用术语表 | 翻译时向翻译服务提供你的[术语表](./glossary.md)词条。 |

此外，字段内容取决于翻译服务类型：

- **Google**——免费，无需配置。
- **Yandex**——需要 API 密钥和 Yandex Cloud 文件夹 ID。
- **DeepL**——需要 API 密钥。
- **LLM 翻译服务**（OpenAI 兼容、Ollama 及类似）共用一组字段：
  - API 密钥 / Base URL——凭据和服务器地址。对于本地提供商，API 密钥为可选项。
  - 模型——通过"检查密钥"获取，它会验证你的凭据并填充模型列表。
  - Token 限制 / 输出 Token 限制——请求和响应的 Token 预算（1000-65536）。
  - Temperature——采样随机性（0.0-2.0）。
  - 思考 / 推理投入——启用支持扩展思考的模型的扩展思考，以及投入的精力。
  - 系统提示词 / 单独翻译系统提示词——发送给模型的指令；均可重置为内置默认值。

类型列表中未包含的提供商（例如 [OpenRouter](https://openrouter.ai/)通过通用的 **OpenAI 兼容**类型接入——只需将 Base URL 指向提供商的 OpenAI 兼容接口地址（OpenRouter 的为 `https://openrouter.ai/api/v1`），并使用该提供商的 API 密钥。

### LanguageTool

配置用于[检查](./text-editing.md#linting) 的 [LanguageTool](https://languagetool.org/) 语法检查器。设置同时支持本地服务器和付费托管 API，但实际测试过的仅有本地服务器。

| 设置 | 说明 |
| ---- | ---- |
| Base URL | 你的 LanguageTool 服务器（本地或托管）。"检查连接"用于验证其可访问性。 |
| 用户名 / API 密钥 | 仅在使用付费托管 API 时需要，以获取 Premium 访问权限。 |
| 母语 | 你的母语，用于针对某些语言对启用易混淆词检查。 |
| 仅启用 | 如果开启，则仅检查下方明确列出的类别/规则——其他一切均被忽略。 |
| 启用/禁用的类别，启用/禁用的规则 | 逗号分隔的规则/类别 ID，用于缩小或精简检查范围。 |
| 首选变体 | 逗号分隔的区域拼写变体，LanguageTool 应优先使用（例如 `en-US` 优于 `en-GB`）。 |
| 词典 | 逗号分隔的额外词典，用于提取词汇。留空则使用默认词典。 |
| 挑剔模式 | 开启对正式文本大多有用的额外规则。 |

### 检查

此处所有内容也可以通过[检查菜单](./text-editing.md#linting)中的"检查"按钮逐项切换——此处是配置和编辑它们的地方，而不仅仅是开关。

- **序列检查**——四个只读表格（文本代码、备注标签、插件命令、注释标签），列出 RPGMTranslate 识别的每个内置插件/标签模式，按类别分组。每行可以设置自定义高亮颜色。
- **自定义检查**——你自己的检查模式，在可编辑表格中：匹配的序列、悬停时显示的提示、是否区分大小写，以及可选的高亮颜色。双击单元格即可编辑。自定义检查可以导出为和从 JSON 文件导入，用于备份或分享。
- **杂项**：
  - 序列替换——在你输入时静默替换的字符序列表（例如 `<<` -> `«`），用于你键盘上没有的非 ASCII 标点。预填充了一些常见项，但默认禁用。
  - 空白字符——哪些 Unicode 码位（`U+XXXX`，逗号分隔）在前导/尾随/连续空白检查中被视为空白。

## 项目

按项目存储。

| 设置 | 说明 |
| ---- | ---- |
| 行长度提示 | 在翻译单元格中此字符数处绘制一条细红线，作为换行参考（0-255）。 |
| 源语言 / 翻译语言 | 源语言和目标语言，用于 [CAT](https://en.wikipedia.org/wiki/Computer-assisted_translation) 匹配。仅限于我们的[文本匹配库](https://github.com/savannstm/language-tokenizer/blob/master/src/lib.rs#L139)支持的语言。 |
| 拼写检查词典 | 用于检查的 Nuspell 词典。获取方式见下方。 |
| 写入编码 | 翻译通常无法用源游戏自身的代码页表示（例如日文 `Shift-JIS` 没有西里尔字母来翻译俄语翻译），且强制使用错误的编码不会明显失败——不可映射的字符会被静默替换为字面的 `&#1055;` 风格数字引用并拼接到输出中。仅在目标引擎构建没有 Unicode 感知文本渲染器可回退时设置写入编码——RPG Maker 2000/2003、XP 和 VX 属于这种情况，它们通过操作系统的传统 ANSI 代码页而非解码 UTF-8 来渲染——**并且**翻译自身的脚本可以放入你选择的代码页中。运行翻译后游戏的人还需要将系统（或区域模拟工具）设置为相同的代码页；Windows 10 1903+ 上，在区域设置中勾选"测试：使用 Unicode UTF-8 实现全球语言支持"可使默认的 UTF-8 输出在这些引擎上同样生效，无需以上任何操作。VX Ace 原生支持 Unicode，因此其默认 UTF-8 可直接工作。 |

### 拼写检查

RPGMTranslate 不附带拼写检查词典——将 `.aff`/`.dic` 文件放入 `APPLICATION_DIR/dictionaries`，它们就会出现在下拉列表中。来源：

- [LibreOffice 词典](https://github.com/LibreOffice/dictionaries)
- [此词典集合](https://github.com/wooorm/dictionaries)

CJK 尚不支持。

### CJK 文本匹配

日语、中文和韩语的 [CAT 匹配](#project) 需要词边界词典（这些语言中没有空格分隔单词），RPGMTranslate 也不附带这些词典——它们是数百兆的文件，否则会使每次安装都膨胀。从 [Lindera 的发布页](https://github.com/lindera/lindera/releases) 获取匹配压缩包并解压，然后将解压文件夹中的文件（`dict.trie`、`dict.words`、`metadata.json` 等）移动到 `APPLICATION_DIR/lindera-dictionaries/<语言>`，使 `dict.trie` 等文件直接位于其中。下次使用该语言时会自动加载——无需重建或重启：

| 语言 | 文件夹 | 要下载的压缩包 |
| ---- | ------ | ------------- |
| 日语 | `lindera-dictionaries/japanese` | `lindera-ipadic-neologd-*.zip`（匹配质量最佳）或 `lindera-ipadic-*.zip`（更小） |
| 中文 | `lindera-dictionaries/chinese` | `lindera-cc-cedict-*.zip` |
| 韩语 | `lindera-dictionaries/korean` | `lindera-ko-dic-*.zip` |

如果语言的文件夹缺失、为空，或其文件嵌套在额外的子文件夹中，则该语言的匹配会报错，而不会静默回退。

### 上下文

翻译时提供给 LLM 翻译服务的自由文本：

- **项目上下文**——整体设定、语气、术语、受众——适用于整个项目。
- **文件上下文**——从列表中选择一个文件，然后写入仅针对该文件的上下文（仅在该文件中出现的角色名、语气变化、限制等）。
