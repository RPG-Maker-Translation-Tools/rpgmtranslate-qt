title: "Массовая обработка"
---

RPGMTranslate позволяет легко применять массовую обработку к переводу. Откройте её через кнопку ![](../assets/construction.svg).

Она запускает скрипт над текстом файлов, выбранных в её меню выбора файлов (по умолчанию ни один файл не выбран), и записывает результат в выбранный вами столбец перевода. Есть три встроенных скрипта:

- **Обрезать** - обрезает начальные, конечные или начальные и конечные пробелы текста.
- **Перенести** - переносит текст по заданной длине в символах (20-255). Кнопка "Использовать значение из настроек" подставляет лимит длины строки проекта (см. [настройки проекта](./settings.md#проект)). См. [как работает перенос](#как-работает-перенос).
- **Латинизировать** - транслитерирует текст в латинские символы.

Эти же три скрипта можно запустить на одной ячейке горячими клавишами "Обрезать ячейку", "Перенести ячейку" и "Латинизировать ячейку", см. [Настройки > Управление](./settings.md#управление).

## Как работает перенос

Перенос старается следовать тому, как игра будет отрисовывать текст, но не может знать реальную ширину всего, так что относитесь к результату как к хорошему приближению и сверяйте его с лимитом длины строки.

- Длина строки считается в символах. Существующие переносы строк сохраняются; переносятся только слишком длинные строки.
- Коды и теги RPG Maker (`\C[2]`, `\fn<Comic Sans>`, `<br>`, коды плагинов, в любом движке) не занимают ширины и никогда не разрываются переносом, даже если в их аргументе есть пробелы. Исключение - коды, которые рисуют что-то, реальный размер чего зависит от игры: значения переменных, имена персонажей и членов отряда, название валюты и иконки. Они считаются как примерное количество символов. Вложенные коды (`\N[\V[3]]`) обрабатываются как один код.
- Коды размера (`\{`, `\}`, `\fs[n]`) учитываются: символы после увеличения шрифта занимают больше места, а после уменьшения - меньше. Чтобы это было точным, укажите в [настройках проекта](./settings.md#лимит-длины-строки) "Размер шрифта подсказки", равный базовому размеру шрифта вашей игры.
- Строки разрываются по пробелам. Японский и китайский текст разрывается между любыми двумя символами, но пунктуация, которая не может начинать или заканчивать строку (например `。`, `、`, `「`), не оказывается на краях строки. Одно слово длиннее строки не разрезается, а просто выходит за её пределы.
- Пробелы, повисшие в конце строки, удаляются.
- Строка остаётся нетронутой, если использует собственный тег движка `<WordWrap>`, или если после переноса она заняла бы больше 4 строк (окно сообщения показывает 4). Строки, оставленные из-за количества строк, записываются в лог приложения.

## Пользовательские скрипты

Вместо этого вы можете написать свой собственный скрипт на JavaScript (с помощью [quickjs-ng](https://github.com/quickjs-ng/quickjs)). Кнопка нового скрипта добавляет скрипт из шаблона; редактируйте его в редакторе скриптов (кнопка с карандашом открывает его в отдельном, более крупном окне с подсветкой синтаксиса), а переименовывайте, редактируя его название в списке скриптов. Пользовательские скрипты сохраняются как `.js` файлы в папку `scripts` [папки данных приложения](./installation.md#файлы-данных-программы), когда проект закрывается или приложение завершает работу, так что они сохраняются между сессиями и ими легко делиться. Любой `.js` файл, который вы туда положите, появится в списке.

Каждый вызов функции скрипта может выполняться не более 15 секунд (время ожидания в `rpgm.exec` не считается), а скрипт может использовать до 64 МиБ памяти.

Скрипт должен определять функцию:

```js
function rpgmLineCallback(
  sourceText,
  translations,
  filename,
  lineNumber,
  options,
) {
  // ...
  return translations;
}
```

Она вызывается один раз для каждой переводимой строки:

- `sourceText` - исходный текст строки.
- `translations` - массив с существующими столбцами перевода строки.
- `filename` - файл, которому принадлежит строка.
- `lineNumber` - индекс строки в этом файле.
- `options` - `{ action, columnIndex, sourceLanguage, translationLanguage, ... }`; `action` - это `"trim"`/`"wrap"`/`"latinize"`/`"custom"`, `columnIndex` - столбец перевода, в который идёт запись, `sourceLanguage`/`translationLanguage` и `fontSize` берутся из настроек проекта, `glossary` - массив включённых терминов глоссария вида `{ term, translation, note }`, а `trimLeading`/`trimTrailing` (для обрезки) или `wrapLength` (для переноса) передают настройки встроенных скриптов.

Верните массив строк, чтобы перезаписать столбцы перевода - элемент массива `i` соответствует `translations[i]`. Возврат `undefined`/`null` для элемента (или более короткого массива, или ничего) оставляет этот столбец без изменений.

### Обработка целого файла

Скрипт может определить `rpgmFileCallback(filename, rows, options)` вместо `rpgmLineCallback` - определение обеих функций считается ошибкой. Она вызывается один раз для каждого файла, что позволяет скрипту отправить много строк в программу за один вызов:

- `rows` - все строки файла по порядку, в виде `{ source, translations, lineNumber, isComment }`. Строки комментариев видны, но никогда не перезаписываются.
- Верните массив с одним элементом на каждую строку. Каждый элемент - либо массив в форме `translations` (с тем же смыслом, что и возвращаемое значение `rpgmLineCallback`), либо `undefined`/`null`, чтобы оставить строку без изменений.

## Что могут скрипты

Помимо обычного JavaScript, пользовательский скрипт может использовать:

- `rpgm.exec(program, args, { stdin, cwd, timeoutMs })` - запускает программу и возвращает `{ code, stdout, stderr }`. Программа ищется сначала в папке `scripts` (поэтому кладите программы, которые вызывает скрипт, рядом с ним), затем в `PATH`, а `cwd` - это папка `scripts`, если не указана другая. Создаёт ошибку, если программа не может запуститься, закрылась или превысила `timeoutMs` (по умолчанию 120000). Ненулевой код выхода показывается.
- `rpgm.readFile(path)` и `rpgm.writeFile(path, text)` - читают и записывают текстовые файлы в UTF-8.
- `rpgm.log(message)` - записывает строку в лог приложения. Когда обработка завершается, последние 30 строк, записанных скриптом, также показываются вам.

Поскольку эти функции могут делать всё, что может ваша учётная запись, при первом запуске пользовательского скрипта вас попросят его разрешить. Ответ запоминается для именно этого текста скрипта; если вы отредактируете скрипт, вас спросят снова. Встроенные скрипты получают только `rpgm.log`.

Так можно использовать ИИ модели: вызывать из скрипта локальный сервер, например Ollama (см. ниже), или запускать Python скрипт, использующий библиотеку на ваш выбор.

### Пример: перевод через Ollama

Это скрипт для [точки перевода скрипта](./settings.md#точки-перевода). Он отправляет текст локальному серверу Ollama через `curl` и возвращает ответ. Замените `model` на модель, которую вы скачали.

```js
function rpgmTranslateCallback(
  text,
  sourceLanguage,
  translationLanguage,
  glossary,
  filename,
) {
  const terms = glossary
    .map((entry) => `${entry.term} = ${entry.translation}`)
    .join("\n");

  const request = {
    model: "gemma3",
    stream: false,
    messages: [
      {
        role: "system",
        content:
          `Translate the user's text from ${sourceLanguage} to ${translationLanguage}. ` +
          "Keep every \\code and [tag] unchanged. Answer with the translation only." +
          (terms ? `\nUse these terms:\n${terms}` : ""),
      },
      { role: "user", content: text },
    ],
  };

  const response = rpgm.exec(
    "curl",
    ["-sS", "http://localhost:11434/api/chat", "-d", "@-"],
    {
      stdin: JSON.stringify(request),
      timeoutMs: 120000,
    },
  );

  if (response.code !== 0) {
    throw new Error(response.stderr);
  }

  return JSON.parse(response.stdout).message.content.trim();
}
```

### Пример: массовый перевод через OpenRouter и LiteLLM

[`examples/openrouter-litellm.js`](https://github.com/RPG-Maker-Translation-Tools/rpgmtranslate-qt/blob/main/examples/openrouter-litellm.js) переводит целые файлы любой моделью OpenRouter. Он использует `rpgmFileCallback`, чтобы собрать строки, у которых целевой столбец пустой, отправляет их частями Python помощнику ([`openrouter_litellm.py`](https://github.com/RPG-Maker-Translation-Tools/rpgmtranslate-qt/blob/main/examples/openrouter_litellm.py), в котором находится системный промпт) через `rpgm.exec`, а помощник обращается к модели через [LiteLLM](https://github.com/BerriAI/litellm).

1. Установите Python 3 и выполните `pip install litellm`.
2. Установите переменную среды `OPENROUTER_API_KEY` перед запуском RPGMTranslate. Ключ читается LiteLLM и никогда не хранится в скрипте.
3. Укажите исходный язык и язык перевода в `Настройки > Проект`. Термины глоссария отправляются модели с каждым запросом.
4. Скопируйте скрипт в папку `scripts`, положите `openrouter_litellm.py` рядом с ним (или куда угодно, и тогда укажите полный путь к нему в `PYTHON_MODULE` в начале скрипта).
5. Откройте меню обработки, выберите скрипт и столбец для перевода, и разрешите скрипт, когда вас спросят.

Измените `MODEL` в начале скрипта, чтобы использовать другую модель. Приложение не отслеживает контекст проекта: чтобы отправлять его (или что-либо ещё) с каждым запросом, заполните `EXTRA_FIELDS` в скрипте и опишите эти поля в системном промпте в `openrouter_litellm.py`, так как модель знает только то, что ей говорит промпт. Переводятся только пустые строки, так что после неудачного запроса (или отмены) уже переведённые строки сохраняются, ошибка записывается в лог приложения, а повторный запуск скрипта продолжает с того места, где он остановился.
